开源桌面机器人调研 · 总报告

ESP-Claw / Ditto 与 StackChan

一句话结论：StackChan 更像“已经做好的机器人身体”，ESP-Claw 更像“让设备具备 AI Agent 能力的运行时”。如果目标是尽快做出可扩展的小机器人，建议先用 StackChan 做硬件，再把独立 Agent、MCP 和家庭自动化服务接上去。

调研范围：官方仓库、官方产品资料、公开文档与许可证信息

先看结论 给决策者的 30 秒版本

选择 StackChan，如果你要

尽快拥有一个能动、能说、能表达的实体机器人。

它已经包含屏幕、摄像头、麦克风、扬声器、舵机、传感器、电池和外壳生态，验证周期短。

选择 ESP-Claw / Ditto，如果你要

把 AI Agent、设备控制和 IoT 协议做成自己的平台能力。

它的优势在运行时、工具调用、Lua 扩展、MCP 和多设备适配，不是完整机器人套件。

项目定位 不是同一种产品

ESP-Claw

Espressif 面向 ESP32 系列设备的 Chat Coding AI Agent 框架。用户可以通过对话定义设备行为，生成的逻辑可以持久化为本地规则。

软件运行时设备 AgentIoT 平台

StackChan

M5Stack 与社区共同发展的开源桌面机器人项目，重点是可购买、可组装、可编程的实体机器人体验。

完整硬件桌面机器人应用生态

架构对照 两条路线如何工作

ESP-Claw 的软件栈

交互入口Telegram、QQ、飞书、微信等 IM 通道；也可接自定义 API
↓
Agent LoopLLM 对话、工具调用、任务编排、上下文与本地结构化记忆
↓
设备能力Lua runtime、Router、本地确定性规则、事件驱动、MCP Server / Client
↓
硬件外设LVGL、I2C、UART、PWM、PCNT、RMT、ADC、USB、BLE HID 等

StackChan 的实体栈

应用 / MODJavaScript / TypeScript 功能、动作、表情、网页工具和 Blockly
↓
Host / 固件底层驱动、传感器、显示、音频、舵机、通信和基础系统能力
↓
机器人硬件CoreS3、触摸屏、摄像头、双麦克风、扬声器、舵机、LED、电池和扩展接口
关键差异：StackChan 的 Host 与 MOD 分离，修改用户功能时不必每次重编译整个底层 Host；ESP-Claw 则把 Agent、工具和设备能力直接融合到 ESP32 设备运行时中。

硬件对照 谁更接近开箱即用

维度ESP-Claw / DittoStackChan / CoreS3
主控定位Ditto 板级配置基于 ESP32-C5，强调连接、低功耗和 IoT 协议。CoreS3 基于 ESP32-S3，双核 240 MHz、16 MB Flash、8 MB PSRAM，更适合多媒体交互。
机器人部件公开资料可确认板级支持，但不足以确认完整量产机器人 BOM、外壳、舵机、电池和采购渠道。公开资料明确包含屏幕、摄像头、双麦克风、扬声器、两个反馈舵机、RGB LED、电池、传感器和外壳安装生态。
扩展接口取决于所选 ESP32 开发板与 ESP-IDF 外设能力。3 个 Grove 接口、microSD、NFC、红外、LEGO 兼容安装孔等。
运动能力需要自行选舵机、电机、结构件和控制策略。水平约 360 度连续旋转，垂直约 90 度；垂直舵机建议限制在约 5 至 85 度。

功能与开发体验

ESP-Claw 强项

对话式定义设备行为、LLM 工具调用、本地规则持久化、Lua 同步与异步执行、多种 API 风格、自定义端点、MCP 和 IM 通道。

StackChan 强项

语音唤醒、语音问答、表情、动作、手机 App、远程视频、ESP-NOW 遥控、舞蹈、OTA、App Center、红外、NFC 与 Home Assistant MCP。

开发方式

StackChan 可使用 Arduino、UiFlow2、PlatformIO、ESP-IDF，也可使用社区 MOD 的 JavaScript / TypeScript 与浏览器工具。

可扩展性评分 基于公开架构的工程判断，不是官方评级

硬件起步
StackChan 更高：部件完整，少做机械整合
软件扩展
两者都强：StackChan 偏应用，ESP-Claw 偏设备 Agent
从零自研
ESP-Claw 更自由，但需要自己补齐硬件与产品化工作
快速验证
StackChan 更快：买到硬件即可开始验证交互
平台化潜力
ESP-Claw 更强：适合沉淀统一设备能力层

成本与许可证

实际落地成本

StackChan：硬件采购成本较明确

主要成本是整机或套件价格、运输、备件和云端 AI 服务。它减少了屏幕、音频、舵机、电池、外壳和装配的隐性成本。

ESP-Claw：软件免费不等于整机便宜

需要额外预算主控板、舵机或电机、结构件、电池、摄像头、麦克风、扬声器、PCB、调试和后续维护。公开资料不足以给出 Ditto 完整量产 BOM 的可靠总价。

许可证注意事项

原始社区 Stack-chan 仓库使用 Apache License 2.0。M5Stack 官方仓库中曾包含 `SCServo_lib` GPLv3 组件，最终产品应逐项核对实际固件依赖和分发义务。

ESP-Claw 及其组件也应以目标提交中的 LICENSE、NOTICE 和第三方依赖声明为准。商业化前应做一次完整的许可证清单审查，不能只看仓库首页。

社区与项目成熟度

StackChan 的优势与限制

有 M5Stack 官方仓库、原始社区仓库、产品资料、3D 外壳、电路图、浏览器模拟器、MOD Gallery 和编辑工具，学习路径清晰。需要注意官方 README 提到仓库更新可能滞后于官方固件和手机 App。

ESP-Claw 的优势与限制

更适合研究 Agent 与设备融合，能把能力下沉到边缘设备。限制是它不是一套完整机器人产品，机械、电源、媒体交互和量产细节需要自行验证。

推荐落地方案 把两个项目组合起来

StackChan负责屏幕、表情、语音、动作、摄像头、传感器和机器人身体
↑↓
Agent / MCP 服务负责对话、记忆、家庭自动化、业务规则、权限和模型切换
↑↓
ESP-Claw 风格适配层把 `look`、`speak`、`set_expression`、`read_sensor` 等高层能力暴露给 Agent

不要优先暴露任意 GPIO 或任意电机控制。先提供高层、可验证、可限幅的工具，例如 `robot.look(direction)`、`robot.speak(text)`、`robot.play_animation(name)` 和 `robot.read_sensor(name)`。

第一阶段：验证想法

  1. 购买 StackChan 或 CoreS3 兼容硬件。
  2. 用现有 MOD、表情和动作能力做最小演示。
  3. 确认你真正需要的传感器、动作和对话流程。

第二阶段：平台化

  1. 部署独立 Agent / MCP 服务。
  2. 为机器人建立稳定的高层能力接口。
  3. 再评估是否把部分 Agent 能力下沉到 ESP-Claw / Ditto。
